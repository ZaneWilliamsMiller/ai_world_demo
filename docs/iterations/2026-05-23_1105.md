## 改动概要

**🧠 NPC大脑升级 - NPC状态感知注入对话（State-Aware Dialogue Behavior）**

本轮将已实现但未启用的 NPC 作息状态感知（`npc_state_for_dialogue`）正式接入对话上下文，使 NPC 的回应行为与其当前状态自然联动。

### 问题诊断

`core.py` 中的 `update_npc_states_from_habits()` 已在每次移动后根据 NPC_HABITS 活跃时段更新 NPC 状态（idle/resting/busy/alert/hostile/traveling），且 `npc_state_for_dialogue()` 已写好详细的行为指引，在 `talk_service.py` 头部已被 import，但在 `build_npc_messages()` 中从未被调用。这导致：

- 深夜休憩的 NPC 与白日闲时的 NPC 在语气、耐心、话语长短上毫无区别
- 状态枚举（resting/busy/alert/hostile）成了摆设——只在前端显示了图标，未影响对话体验
- NPC 失去了"生物钟真实感"这一关键叙事维度

### 修改内容

**`backend/services/talk_service.py`**（1 处插入）

在 `build_npc_messages()` 的动态上下文层中，于 `vigor_status_block` 之后插入 NPC 状态感知块：

```python
# ── NPC 状态感知：将作息状态注入对话（idle/resting/busy/alert/hostile）──
state_block = npc_state_for_dialogue(p, npc_id)
if state_block:
    dyn_parts.append(state_block)
```

### 行为效果

| NPC 状态 | 对话行为 | 示例 |
|----------|----------|------|
| idle | 正常对话，无特殊提示 | 无注入块 |
| resting（白日） | 语气倦怠，话短（3~6句），能推便推 | "嗯...何事？" |
| resting（深夜） | 被搅醒，语气带火（2~5句），可逐客 | "这时候来扰人清静？" |
| busy | 手上不停，话急促简短 | "等——这批货得先入库..." |
| alert | 话里有话，暗中留意 | "阁下从哪里来？半夜赶路可不太平。" |
| hostile | 摆出不好惹的派头，寸步不让 | "再往前一步，就别怪我不客气。" |

### 设计原则

- 状态感知块注入在动态层（不缓存），因为状态随时间随时变化
- 仅当状态非 idle 时才注入（idle 是默认态，不需要特别提示）
- 块末尾明确指示"不要复述此提示块"，避免 LLM 复读状态标签
- 不违反 Prompt Cache 架构（状态块在 uncached 动态层）
- 与 `update_npc_states_from_habits` 形成完整闭环：移动→状态更新→对话注入
