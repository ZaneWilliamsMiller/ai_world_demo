# 活纸·每日迭代 — 2026-05-24_0802

## 方向
🐛 Bug 修复 — 存档系统 Memory 反序列化崩溃（静默丢失全部记忆）

## 改动概要

### 问题
`save_system.py` 的 `_deserialize_player()` 在还原 `AgentMind` 中的 `Memory` 对象时存在 **三处致命缺陷**，导致所有存档加载静默失败（`load_game()` 返回 `None`，角色进度丢失）：

1. **`anchor=` 误写为构造参数**：`Memory` 数据类的字段名为 `is_anchor`，但反序列化代码传的是 `anchor=bool(...)`，Python 直接抛 `TypeError: __init__() got an unexpected keyword argument 'anchor'`
2. **缺少必填字段**：`Memory` 的 `id`、`created_at`、`last_accessed` 三个无默认值字段未传入构造函数，Python 抛 `TypeError: __init__() missing required argument`
3. **`linked_memory_ids` 未序列化/反序列化**：`_mind_to_dict()` 漏掉了此字段，导致顿悟防重复链接在存档加载后失效

此外 `Memory.to_dict()` 未输出 `created_at` / `last_accessed`，即使修复构造函数，`last_accessed` 也会丢失——记忆的 recency 衰减在加载后全部重置为"刚刚访问"，导致检索质量退化。

### 影响
- **任何包含 NPC 记忆的存档都无法加载**：`load_game()` 被 `try/except` 兜底，异常被吞掉，函数返回 `None`
- 前端表现为：刷新页面后角色消失，需重新创建
- 新角色无记忆时不触发此 Bug（Memory 列表为空），所以问题在前期不易发现，但玩家积累几轮对话后必现

### 改进

#### `backend/memory.py`
- `Memory.to_dict()` 新增 `created_at` 和 `last_accessed` 输出，确保存档保留完整的时间戳信息
- 加载后记忆的 recency 衰减能正确延续，不会全部被标记为"刚刚访问"

#### `backend/systems/save_system.py`
- `_mind_to_dict()` 新增 `linked_memory_ids`（set→list 序列化），保证顿悟防重复链接持久化
- `_deserialize_player()` 完全重写 Memory 构造逻辑：
  - `is_anchor=` 替代错误的 `anchor=`
  - 补齐 `id`（从存档读取，缺省生成 uuid）、`created_at`、`last_accessed`
  - 补齐 `created_day`、`created_shichen` 移入构造函数（不再赋值后置）
- `_deserialize_player()` 还原 `linked_memory_ids`（list→set）

### 不影响
- Prompt Cache 架构：存档系统与 talk_service 缓存层无交互
- API 端点：无接口变化
- 新角色创建流程：不受影响
