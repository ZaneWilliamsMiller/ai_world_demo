# 迭代记录 · 2026-05-25 06:00

## 改动概要

🐛 **Bug 修复**：`respawn_at_supply_point` 复活时清除 `enslaved` 与 `ended` 状态死锁

## 问题描述

当玩家被奴役（`enslaved=True, ended=True`）后，若因体力/心气归零触发 `maybe_collapse_from_attrs` 并进入 `respawn_at_supply_point`（非真实江湖模式），复活逻辑清除了 `move_locked`、`dead`、`trap` 等状态，但**未清除 `enslaved` 与 `ended` 标记**。

这导致：
1. 玩家复活后仍处于 "奴役" + "已收束" 状态
2. `/api/move` 端点被 `enslaved` 检查拦截（HTTP 400："你已沦为囚役"）
3. `/api/move` 端点同时被 `ended` 检查拦截（HTTP 400："本局已收束"）
4. 玩家陷入不可恢复的死锁——复活了但动不了

## 修复内容

**文件**：`backend/systems/save_system.py` — `respawn_at_supply_point()`

在复活清状态时新增两行：

```python
p.enslaved = False
p.enslaved_reason = None
p.ended = False
p.ending_label = None
```

逻辑：`respawn_at_supply_point` 本质上是 "从死亡/枯竭中苏醒"，应当是一次完整的重置——包括解除非自愿的终局状态（奴役/收束）。复活后玩家应能重新行动。
