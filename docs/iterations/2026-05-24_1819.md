## 问题发现

`condense_old_observations` 函数在触发记忆凝结时，仅给旧观察打上 `[已凝]` 前缀并降低重要性，但**不从 `mind.items` 中删除**这些已被凝结的观察记忆。

这导致三个问题：
1. 已凝结的观察继续参与检索（`retrieve()` 遍历所有 `mind.items`），污染召回结果
2. 记忆流持续膨胀——凝结操作没有实际减少检索条目数，失去 CMA（Cognitive Memory Agent）防膨胀的核心价值
3. `[已凝]` 前缀仅通过降低文本匹配度间接削弱召回，不如直接排除高效

## 改动内容

### `backend/memory.py` — `condense_old_observations()`

将旧观察的"前缀标记+降权"策略替换为"直接删除+摘要锚点"：

```diff
-    标记被凝结的观察（不删除，但前缀标识）
-    for m in to_condense:
-        m.text = f"[已凝] {m.text}"
-        m.importance = max(1.0, m.importance * 0.3)
+    标记被凝结的观察：从记忆流中移除（不再参与检索）
+    to_condense_ids = {m.id for m in to_condense}
+    mind.items = [m for m in mind.items if m.id not in to_condense_ids]
```

**保留不变**：`condensation` 类记忆作为摘要锚点继续写入，包含按主题聚类的冷凝摘要。
