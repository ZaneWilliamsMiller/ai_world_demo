## 改动概要

**🐛 Bug修复 - 后台异步任务异常处理与日志增强（Background Task Error Visibility）**

本轮修复了后台异步任务中异常静默吞没的问题，补全日志输出使其可追踪。

### 问题诊断

`agent_service.py` 和 `routes.py` 中共有 3 处后台异步任务（`bg_reflect`、`bg_plan_for_npcs`、`_bg_encounter`），其 `try/except` 块中均以 `pass` 或空 `continue` 吞噬所有异常——包括 LLM API 调用失败、JSON 解析错误、网络超时等。当 NPC 反思/计划/奇遇失败时，服务端无任何日志痕迹，生产环境中极难定位问题。

### 修改内容

1. **`backend/services/agent_service.py`**
   - 新增 `import logging` 与模块级 logger `agent_service`
   - `bg_reflect`：`except Exception: pass` → `except Exception as e: log.warning("bg_reflect failed for npc=%s: %s", npc_id, e)`
   - `bg_plan_for_npcs`：`except Exception: continue` → `except Exception as e: log.warning("bg_plan_for_npcs failed for npc=%s: %s", nid, e); continue`

2. **`backend/api/routes.py`**
   - `_bg_encounter`：`except Exception: pass` → `except Exception as e: logging.getLogger("routes").warning(...)`

### 设计原则

- 后台任务是 **fire-and-forget** 语义，不应因异常阻断主流程 → 保持 `try/except` 结构不变
- 但必须留痕：出问题时至少知道「哪个 NPC 的什么任务在何时失败」
- 日志级别用 `warning`（非 `error`），避免刷爆日志，因为单次 LLM 超时不应视为致命错误
- 不违反 Prompt Cache 架构（未改动 talk_service.py 静态/动态层）
