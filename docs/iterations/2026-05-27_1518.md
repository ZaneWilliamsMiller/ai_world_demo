## 改动概要

### 1. 代词消解实体白名单动态化

**问题：** `memory.py` 中 `PERSON_NAMES` / `PLACE_NAMES` / `ALL_ENTITY_KEYWORDS` 为硬编码常量，仅覆盖 16 个人名和 14 个地名。当 NPC 数据更新时（如新增 `jintang`/`tiegu`/`xuanzhen` 等 NPC），代词消解无法识别这些新 NPC 的名字，导致「他后来怎样了」等代词查询检索命中率极低。

**修复：**
- 新增 `_build_dynamic_entities()` 函数，从 `NPCS`/`NPC_HABITS`/`MAPS` 数据自动提取人名、地名
- 构建策略：NPC name 去括号清理后提取全称+2~3字后缀、NPC short 直接入库、NPC 出没地点入库、地图 portal 地名入库
- 新增 `init_entity_keywords()` 初始化函数，在 `app.py` startup 事件中调用
- `_resolve_deictic` 和 `build_retrieval_query` 内部改为调用 `_get_xxx()` 动态函数
- 保留硬编码兜底：数据源缺失时不空白
- 模块级常量仍在 `init_entity_keywords()` 后可用（向后兼容）

**效果：** PERSON_NAMES 从 16 → 69，PLACE_NAMES 从 14 → 32，覆盖所有 NPC 名和地名。

### 2. 记忆摘要情感增强

**问题：** `_summarize_for_memory` 对所有对话生成等质等量的摘要——无论是 NPC 心平气和还是怒发冲冠，记忆都一视同仁。这不符合人类「情绪锚定记忆」的认知规律。

**修复：**
- 根据 NPC 当前唤醒度（arousal）和效价（valence）调制摘要丰富度
- **高唤醒度**（≥7）：记录更多对话细节（first_line 从 50→80 字）、附注情绪状态
- **强效价**（|valence| ≥ 4）：记录心境缘由（affect_cause），保留情感语境
- **平静态**：保持原有简洁摘要格式
- 摘要长度上限仍为 280 字，不影响记忆存储

## 设计取舍

1. **为什么用延迟导入而非静态白名单？** — 避免 `memory.py` 和 `npcs_data.py` 之间的循环依赖，`_build_dynamic_entities()` 在首次调用时才从数据模块拉取
2. **为什么保留模块级常量？** — 其他模块可能已 `from backend.memory import PERSON_NAMES`，保持向后兼容
3. **为什么摘要增强不用 LLM？** — 记忆摘要是每次对话必写的热路径，增加 LLM 调用会显著增加延迟；启发式足够模拟核心效果
